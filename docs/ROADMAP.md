# Code Link 下一步

当前版本提供 Windows + Android 客户端，以及 macOS + iOS 原生客户端。Apple 端支持 LAN、托管终端、Codex 授权和 A/B 提醒；iOS 后台暂停连接。以下为按用户使用障碍排列的计划，尚未列出的发布日期由实际验收决定。

| 优先级 | 要改善的操作 | 完成标准 |
| --- | --- | --- |
| P0 | 首次连接时不知道先操作哪一端 | 两端显示安装、调试授权、设备连接、终端选择的进度；常见失败有可执行的下一步 |
| P0 | 下载后还要另装 .NET | 提供包含运行时的 Windows 包，在未安装 .NET 的干净 Windows 上完成验收 |
| P0 | 升级与安装来源的信任 | 维护稳定 Android 发布签名、升级说明和 SHA-256；制定 Windows 签名和版本检查方案 |
| P0 | 从 README 看不出实际工作流程 | 录制从真实任务、授权到 A/B 完成横幅的短视频，展示操作和耗时 |
| P1 | 英文用户看得懂 README，操作仍困难 | 提取 Android、WPF 中的界面字符串，提供简体中文和英文切换并验证两种语言 |
| P1 | 手机上横向工具栏和状态区域拥挤 | 360dp / 412dp 手机及横屏平板上不裁切操作；键盘弹出时仍能输入和发送 |
| P1 | 状态未知、失败和完成不容易理解 | 增加文字状态说明和上次同步时间，保留未知状态；提醒不能把断线或失败算为成功 |
| P1 | 多窗口和长任务更难定位 | 搜索、置顶、状态筛选；先验证多个真实并行任务的切换、输入归属和提醒 |
| P1 | Wi-Fi 与不同设备的可靠性证据不足 | 完成 LAN 真机连接、蓝牙锁屏、跨厂商后台和 8 小时连接及耗电记录 |
| P2 | 修改 Android 页面需要阅读大量内联 Java | 拆分界面与连接状态、迁移标准资源布局和 Gradle，确保新环境可构建 |
| P1 | Apple 发布与真实设备验证 | Developer ID 公证、TestFlight、iPhone / iPad 真机网络和电池验收 |
| 待需求验证 | Linux、WSL 与更多代理 | 先收集具体需求与可测试设备，再选择下一平台或协议 |

欢迎从[问题模板](https://github.com/ZARADEE/code_LINK/issues/new/choose)提交设备兼容记录或实际操作障碍。翻译准备、首次连接文案和设备验收是当前适合参与的工作。
